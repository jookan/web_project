화면의 접근 검사와 별도로 `firestore.rules`에서 실제 데이터 접근 권한을 검사합니다.

## 악보 기능

HTML은 `sheet_functions.js` 하나를 `type="module"`로 불러온다.
나머지 파일은 이 파일의 `import`를 따라 연결된다.

| 파일 | 역할 |
| --- | --- |
| `sheet_functions.js` | 시작점. 현재 악보 선택, 이전·다음 이동, 기능 연결 |
| `score_library.js` | 파일 선택, 중복 확인, 악보 객체 생성, 목록 버튼 |
| `pdf_viewer.js` | PDF.js 준비, PDF 읽기, 페이지 그리기, 화면 크기 대응 |
| `practice_settings.js` | BPM·박 수 검사, 연주 순서 편집·추가·삭제, 예상 시간과 현재 단계 표시 |
| `auto_turn.js` | 단계별 시간 계산, 시작·정지, 순서에 따른 자동 넘기기 |
| `metronome.js` | 자동 넘기기 단계의 박자 소리 생성 및 정지 |
| `score_storage.js` | UID별 IndexedDB의 PDF 원본과 Firestore의 악보 설정 저장·복원 |
| `vendor/pdfjs/` | 외부 PDF.js 라이브러리. 직접 수정하는 학습 코드가 아님 |

## 악보를 선택했을 때

1. `score_library.js`가 메인에서 전달받은 `selectScore(score)`를 호출한다.
2. 메인은 선택한 악보를 `activeScore`에 저장한다.
3. `showPracticeSettings(score)`가 입력값과 연주 순서를 표시한다.
4. `renderPage(score)`가 해당 악보의 현재 페이지를 그린다.

각 기능은 같은 `score` 객체를 전달받는다. 설정을 다른 객체로 복사하지
않으므로, BPM을 바꾸고 다른 악보를 선택했다 돌아와도 변경값이 유지된다.
PDF 원본은 UID별 IndexedDB에, 로그인한 사용자의 설정은 Firestore에도 저장한다.
다른 기기에서는 같은 PDF를 선택해 설정을 복원한다. 게스트는 로컬에만 저장한다.

공부할 때는 메인의 `selectScore()`부터 시작해 호출하는 함수로 따라가면 된다.

## 자동 넘기기 사용 방법

1. PDF를 추가하고 기본 BPM과 마디당 박 수를 설정한다.
2. 연주 순서 표에서 각 단계의 PDF 페이지 번호와 연주할 마디 수, 필요한 경우 BPM을 지정한다.
   BPM을 비우면 기본 BPM을 따르고, 숫자를 입력하면 해당 단계에만 적용한다.
   같은 페이지 안에서 속도가 바뀌면 같은 페이지를 여러 행으로 나눠 각 구간의 마디 수와 BPM을 입력한다.
3. 반복할 때는 같은 페이지 번호를 다시 넣는다. 예: `1 → 2 → 1 → 2 → 3`.
   `현재 페이지 추가`는 지금 보고 있는 PDF 페이지를 순서 끝에 넣으며,
   각 행의 `×`는 그 연주 단계를 삭제한다.
4. `처음부터 시작`을 누르면 1단계부터 자동 진행한다.
5. `정지`를 누르면 멈춘다. 다시 시작하면 첫 단계부터 시작한다.

한 단계의 시간은 `(60 / (단계 BPM 또는 기본 BPM)) × 마디당 박 수 × 마디 수`초다.
BPM 120, 마디당 4박, 16마디면 32초다. BPM의 한 박과 입력한 박 수의
기준을 맞춰 사용한다. 페이지가 그려진 뒤부터 시간을 센다.

실행 중에는 설정을 잠근다. 수동 페이지 이동, 다른 악보 선택, 파일 선택,
탭 이탈 시 자동으로 정지한다. 마지막 단계도 설정한 시간이 지난 뒤 종료한다.
빈 연주 순서는 시작할 수 없다.

메트로놈을 켜면 자동 넘기기 중 소리가 나고 마디 첫 박을 강조한다.
페이지를 그리는 동안에는 잠시 소리가 멈추고 다음 단계가 준비되면 해당 단계의 BPM으로 다시 시작한다.
메트로놈은 BPM 600까지 지원한다. PDF의 반복 기호를 자동으로 인식하지 않으므로
실제 연주할 순서와 마디 수는 직접 입력한다.

## 악보 모듈 기능명세

대상 화면은 `pages/sheet_uploading.html`이다. 아래 함수는 `sheet_functions.js`에서
직접 호출하거나, 다른 악보 모듈을 거쳐 호출한다. 화면의 버튼·상태 문구를 연결하는
역할은 `sheet_functions.js`, 입력값 편집은 `practice_settings.js`가 맡는다.

### 공통 데이터

```js
score = {
    id,             // 저장 자료를 구분하는 문자열
    file,           // 사용자가 선택한 PDF File
    name,           // 화면에 표시할 파일 이름
    pdf,            // PDF.js가 읽은 문서
    button,         // 악보 목록의 버튼
    pageNumber,     // 현재 화면에 표시하는 PDF 페이지 (1부터 시작)
    practice: {
        bpm: 120,
        beatsPerBar: 4,
        metronome: false,
        steps: [
            { pageNumber: 1, bars: 8 },
            { pageNumber: 1, bars: 8, bpm: 90 }
        ]
    }
};
```

`score.pageNumber`는 현재 화면 위치이고, `steps`는 앞으로 연주할 순서다.
단계에 `bpm`이 없으면 `practice.bpm`을 사용한다. 같은 PDF 페이지를 여러 단계에
넣을 수 있으며, 마디 위치나 악보 기호를 자동으로 인식하지는 않는다.

### auto_turn.js — 연주 순서와 자동 넘기기

| 함수 | 입력 | 반환·결과 |
| --- | --- | --- |
| `getStepBpm(practice, step)` | 기본 설정, 한 단계 | 적용할 BPM. 1 미만 또는 유한한 숫자가 아니면 예외 |
| `getStepDurationMs(practice, step)` | 기본 설정, 한 단계 | `(60 / 적용 BPM) × 박 수 × 마디 수 × 1000` 밀리초 |
| `initializeAutoTurn(onPageChange, onPlaybackChange, onStepReady)` | 페이지 표시·상태 표시·메트로놈 콜백 | 화면과 소리 모듈의 연결 함수 등록 |
| `startAutoTurn(score)` | 선택한 악보 | 첫 단계부터 진행하는 Promise. 실행 중 중복 시작은 무시 |
| `stopAutoTurn(message, isError)` | 선택적인 종료 문구·오류 여부 | 타이머 취소, 실행 상태 해제, 종료 상태 알림 |
| `isAutoTurning()` | 없음 | 자동 진행 중이면 `true` |

- 시작 전에 모든 단계의 페이지 범위, BPM, 정수인 박 수·마디 수, 타이머 범위를 검사한다.
- `onPageChange(score, pageNumber)`가 `true`로 완료된 뒤 해당 단계의 시간을 센다.
- `onStepReady(practice, durationMs)`에는 해당 단계에 적용할 BPM·박 수·메트로놈 여부를 전달한다.
- 진행 상태는 약 200ms마다 `running`, `stepIndex`, `totalSteps`, `pageNumber`, `remainingMs`로 전달한다.
  페이지 준비 중 `remainingMs`는 `null`이다. 종료 시에는 `running: false`, `message`, `isError`를 전달한다.
- 마지막 단계의 시간까지 지난 뒤 정지한다. 일시정지·이어서 재생은 제공하지 않는다.
- 실행 번호로 이전 타이머와 늦게 완료된 페이지 표시를 무효화한다. 이 검사는 정지 후 재시작에 필요하다.

### metronome.js — 박자 소리

| 함수 | 입력 | 반환·결과 |
| --- | --- | --- |
| `prepareMetronome()` | 없음 | AudioContext 생성·재개 Promise. 시작 버튼 클릭 안에서 호출 |
| `startMetronome(practice, durationMs)` | 단계별 BPM·박 수·활성 여부, 단계 시간 | 이전 소리를 멈추고 단계의 박자 예약 |
| `stopMetronome()` | 없음 | 예약 타이머와 재생 중인 소리를 정지 |

- Web Audio API로 마디 첫 박은 1000Hz, 나머지는 700Hz의 짧은 소리를 만든다.
- `playBeat()`는 한 박의 소리 생성·종료·오디오 노드 정리를 담당하는 내부 함수다.
- `60 / BPM`초 간격으로 박자를 배치하고 약 25ms마다 다음 0.12초 구간을 미리 예약한다.
- 메트로놈이 꺼져 있거나 AudioContext가 준비되지 않았으면 소리를 내지 않는다.
- BPM 600 제한과 시작 오류 표시는 `sheet_functions.js`가 처리한다.
  정지 또는 다음 페이지 준비 시에도 메인에서 `stopMetronome()`을 호출한다.

### pdf_viewer.js — PDF 읽기와 화면 표시

| 함수 | 입력 | 반환·결과 |
| --- | --- | --- |
| `showStatus(message, isError)` | 안내 문구·오류 여부 | `#viewer-status` 문구와 오류 스타일 갱신 |
| `prepareViewer()` | 없음 | PDF.js와 worker 경로 준비. 성공하면 `true`, 실패하면 `false`인 Promise |
| `loadPdfFile(file)` | PDF File | PDF.js 문서 Promise. 잘못된 파일·암호 오류는 호출자에게 전달 |
| `renderPage(score)` | PDF 문서와 현재 페이지를 가진 악보 | 표시 성공 여부를 `boolean`으로 반환하는 Promise |
| `observeViewerResize()` | 없음 | PDF 표시 영역의 크기 변경 감지 시작 |

- PDF 원본을 ArrayBuffer로 읽으며 서버에 업로드하지 않는다.
- PDF의 비율과 회전을 반영해 표시 영역 안에 맞추고, 고해상도 화면은 배율 2까지 반영한다.
- 임시 canvas에 그리기가 끝난 뒤 화면 canvas에 복사해 미완성 화면 노출을 줄인다.
- 새 그리기가 시작되면 이전 작업을 취소하고, 렌더링 번호가 오래된 결과는 반영하지 않는다.
- 페이지 표시 실패는 안내 문구와 `false`로 전달한다. 자동 넘기기는 이 결과를 받아 정지한다.
- `ResizeObserver`로 표시 영역을 감지하고 약 100ms 후 다시 그린다.
  그리기 중인 경우 완료 후 크기 변경을 처리한다. 창 크기 이벤트를 중복 등록하지 않는다.

### score_library.js — 파일 선택과 내 악보 목록

| 함수 | 입력 | 반환·결과 |
| --- | --- | --- |
| `initializeScoreLibrary(onSelectScore, onLoadingChange, onBeforeFileSelect)` | 악보 선택·읽기 상태·파일 선택 전 콜백 | 업로드 버튼과 파일 입력 이벤트 등록 |
| `restoreScoreLibrary(onSelectScore)` | 선택 콜백 | 저장 자료로 목록을 복원하고 첫 악보를 선택하는 Promise |
| `updateLibraryButtons(disabled, activeScore)` | 잠금 여부·선택된 악보 | 업로드·목록 버튼의 활성 상태와 선택 표시 갱신 |

- 내부 `addScore()`가 PDF 내용의 SHA-256으로 중복을 확인하고 `score` 객체와 목록 버튼을 만든다.
  같은 내용이면 파일 이름이 달라도 기존 악보를 재사용한다.
- 예전 `[파일 이름, 크기, 수정 시각]` 형식의 ID도 조회하므로 기존 저장 자료를 유지한다.
- 새 악보의 기본 설정은 BPM 120, 마디당 4박, 페이지마다 16마디다.
- 내부 `isValidPractice()`로 저장된 BPM·박 수·단계 페이지·마디 수를 확인한다.
  설정 형식이 유효하지 않으면 기본 설정을 사용하며, 마지막 페이지가 범위를 벗어나면 1페이지로 복원한다.
- DB에 설정만 있고 이 브라우저에 PDF가 없으면 `PDF 선택 필요` 버튼을 만든다.
  같은 내용의 PDF를 선택하면 설정을 연결하고 해당 버튼을 실제 악보 버튼으로 바꾼다.
- 예전 공용 IndexedDB에 자료가 있으면 `기존 브라우저 악보 가져오기` 버튼을 제공한다.
- PDF 확장자가 아니면 거부한다. 실제 파일 분석 실패와 암호 오류는 별도 문구로 알리고
  파일 입력값과 읽기 상태를 초기화해 다시 선택할 수 있게 한다.
- 파일명·크기·수정 시각만으로 중복을 먼저 판정하던 경로는 제거했다.
  중복 확인은 내용 해시 한 곳에서 처리하며, 파일 메타데이터는 `score.file`에서 읽는다.

### score_storage.js — 브라우저 원본과 Firestore 설정

| 함수 | 입력 | 반환·결과 |
| --- | --- | --- |
| `openScoreStorage()` | 없음 | 인증 복원 후 로컬·DB 자료를 합쳐 반환하는 Promise |
| `savedScore(id)` | 저장 ID | 메모리 Map에 있는 저장 자료 또는 `undefined` |
| `saveScore(score)` | PDF File과 설정을 가진 악보 | 로컬 저장 시작, 로그인 상태이면 DB 저장 예약. 반환값 없음 |
| `hasLegacyScores()` | 없음 | 예전 공용 저장소에 자료가 있는지 반환하는 Promise |
| `importLegacyScores()` | 없음 | 현재 계정 저장소에 없는 예전 자료를 복사하고 복사한 개수를 반환하는 Promise |

| 저장 위치 | 저장하는 내용 |
| --- | --- |
| IndexedDB `sheet-music-library-{uid}` / `scores` | ID, PDF File, 마지막 페이지, 연습 설정, DB 반영 대기 여부인 `cloudDirty` |
| 미로그인 IndexedDB `sheet-music-library-guest` | PDF 원본과 설정. DB에는 전송하지 않음 |
| Firestore `users/{uid}/scores/{문서 키}` | `scoreId`, 파일 이름·크기·수정 시각, 마지막 페이지, 연습 설정, 갱신 시각 |
| 예전 IndexedDB `sheet-music-library` | 가져오기 원본. 복사 후에도 삭제하지 않음 |

**불러오기 흐름**

1. Firebase 인증 복원을 기다리고 UID별 IndexedDB를 연다.
2. 브라우저 자료를 `records` Map에 읽는다.
3. 로그인한 사용자는 내부 `loadCloudScores()`로 `users/{uid}/scores`를 조회한다.
4. 같은 ID의 로컬 PDF는 유지하고 DB에서 읽은 마지막 페이지와 연습 설정을 연결한다.
5. `cloudDirty`인 로컬 자료는 서버 값으로 덮어쓰지 않고 DB 저장을 재시도한다.
6. PDF가 없는 DB 자료도 목록에 반환한다. 실제 PDF 선택과 화면 복원은 `score_library.js`가 맡는다.

**저장 흐름**

1. `structuredClone()`으로 현재 연습 설정을 복사해 이후 편집과 저장 중인 값을 분리한다.
2. 로컬 자료를 갱신하고 IndexedDB 쓰기를 시작한다.
3. 로그인 상태에서는 같은 악보의 연속 변경을 500ms 동안 모아 마지막 값만 DB 쓰기 큐에 넣는다.
4. 내부 `syncMetadata()`가 계정 일치를 확인하고 순서대로 `setDoc()`을 실행한다.
5. 최신 자료가 DB와 로컬에 모두 반영되면 메모리의 `cloudDirty`를 해제한다.
   더 최신 변경이 있으면 이전 저장 완료로 해당 변경의 대기 상태를 지우지 않는다.
6. 탭이 숨겨지면 내부 `flushScoreWrites()`로 500ms 대기 중인 항목을 즉시 큐에 넣는다.
   브라우저를 강제 종료할 때 원격 저장 완료까지 보장하는 기능은 아니다.

저장 실패는 `#storage-status`에 표시한다. DB 쓰기 실패 시 로컬 변경을 유지하고 다음 페이지
진입에서 재시도한다. DB 읽기 실패 시에는 읽을 수 있었던 로컬 자료를 반환한다.
`saveScore()`는 완료를 기다릴 수 있는 Promise를 반환하지 않으므로 호출 직후 DB 저장이
완료됐다고 해석하면 안 된다.

PDF 원본은 Firestore에 저장하지 않는다. 따라서 다른 기기에서 설정 목록은 조회할 수 있어도
PDF 표시에는 같은 원본을 다시 선택해야 한다. 실제 프로젝트의 인증·규칙·네트워크 상태에 따른
조회 성공 여부와 소스에 구현된 조회 흐름은 구분해서 확인해야 한다.

### 화면에서의 연결 순서

```text
sheet_uploading.html
  → sheet_functions.js: 화면 이벤트와 모듈 연결
  → pdf_viewer.prepareViewer(): PDF.js 준비
  → score_library.restoreScoreLibrary()
      → score_storage.openScoreStorage(): 로컬 자료 + Firestore 설정
      → pdf_viewer.loadPdfFile(): 원본이 있으면 PDF 문서 생성
      → selectScore(): 설정 표시 + pdf_viewer.renderPage()

업로드 → score_library.addScore() → score_storage.saveScore() → selectScore()
설정 편집 → practice_settings → score_storage.saveScore()
처음부터 시작 → auto_turn → PDF 표시 → 해당 단계 메트로놈 → 다음 단계
정지·수동 이동·탭 이탈 → auto_turn 정지 → metronome 정지
```

현재 다섯 파일의 공개 기능은 위 흐름이나 기존 자료 가져오기에서 사용한다.
Firestore 읽기·쓰기, PDF 재선택 안내, 기존 자료 가져오기는 유지한다.
정리한 항목은 중복 파일 검사, 사용하지 않는 메타데이터 복사, 중복 크기 변경 감지,
중복 저장 상태 변수, 외부에서 사용하지 않는 `flushScoreWrites`의 `export`다.
